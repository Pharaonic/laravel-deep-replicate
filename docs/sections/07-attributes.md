## Attributes

### Root and path configuration

The builder's `exclude()`, `with()`, `generate()` and `transform()` configure the root copy only. `configure()` gives a `RelationRule` for one copied path, with the same methods plus `withoutEvents()` and `preserveTimestamps()`.

- ===Trait

  ```php
  use Pharaonic\Laravel\DeepReplicate\RelationRule;
  use Pharaonic\Laravel\DeepReplicate\ReplicationContext;

  $order->deepReplicate('items')
      ->exclude(['external_ref'])
      ->with(['status' => 'draft'])
      ->generate('slug', fn (Order $source, ReplicationContext $context) => 'order-copy-'.bin2hex(random_bytes(6)))
      ->transform(function (array $attributes, Order $source, ReplicationContext $context): array {
          $attributes['number'] .= '-COPY';

          return $attributes;
      })
      ->configure('items', function (RelationRule $rule): void {
          $rule->exclude(['external_id'])->with(['state' => 'pending']);
      })
      ->replicate();
  ```

- ===Facade

  ```php
  use Pharaonic\Laravel\DeepReplicate\Facades\DeepReplicate;
  use Pharaonic\Laravel\DeepReplicate\RelationRule;
  use Pharaonic\Laravel\DeepReplicate\ReplicationContext;

  DeepReplicate::for($order)
      ->copy('items')
      ->exclude(['external_ref'])
      ->with(['status' => 'draft'])
      ->generate('slug', fn (Order $source, ReplicationContext $context) => 'order-copy-'.bin2hex(random_bytes(6)))
      ->transform(function (array $attributes, Order $source, ReplicationContext $context): array {
          $attributes['number'] .= '-COPY';

          return $attributes;
      })
      ->configure('items', function (RelationRule $rule): void {
          $rule->exclude(['external_id'])->with(['state' => 'pending']);
      })
      ->replicate();
  ```

### Order of operations

For every copy:

1. Laravel's `replicate()` runs on the source (its `replicating` event fires). The primary key, the timestamps and the unique id columns are dropped. The source's loaded relations are removed from the copy.
2. `exclude` removes attributes.
3. `with` sets attributes through `setAttribute()`, so mutators and casts apply.
4. `generate` callbacks run once per copied record, in registration order.
5. `transform` callbacks receive and return the raw (stored) attributes, in registration order.
6. The engine sets the linking keys of the selected relations.
7. `beforeModel` callbacks run, then the copy is saved.

Raw values are copied as stored. JSON columns are not re-encoded, and a value encrypted by a mutator keeps its ciphertext, so it still decrypts to the same plaintext. `$fillable`, `$guarded` and `$hidden` never drop an attribute, because nothing is mass assigned.

### Protected attributes

The primary key and every linking key managed by a selected relation are protected: a `BelongsTo` foreign key, a `MorphTo` id and type, and the foreign key of a copied child. Changing one through `exclude`, `with`, `generate`, `transform` or `beforeModel` throws `ProtectedRelationshipAttributeException`. Foreign keys of unselected relations are yours to change:

- ===Trait

  ```php
  $order->deepReplicate('items')->with(['assigned_customer_id' => $bob->id])->replicate();
  ```

- ===Facade

  ```php
  DeepReplicate::for($order)->copy('items')->with(['assigned_customer_id' => $bob->id])->replicate();
  ```

### Unique values

Nothing is suffixed automatically. A unique slug, SKU or email copied as is fails the insert and rolls back the replication. Give it a value explicitly:

- ===Trait

  ```php
  $order->deepReplicate('items')
      ->generate('slug', fn () => Str::slug($order->number.'-'.Str::random(6)))
      ->configure('items', fn (RelationRule $rule) => $rule->generate('sku', fn (OrderItem $item) => $item->sku.'-2'))
      ->replicate();
  ```

- ===Facade

  ```php
  DeepReplicate::for($order)
      ->copy('items')
      ->generate('slug', fn () => Str::slug($order->number.'-'.Str::random(6)))
      ->configure('items', fn (RelationRule $rule) => $rule->generate('sku', fn (OrderItem $item) => $item->sku.'-2'))
      ->replicate();
  ```

### Primary keys, UUIDs and ULIDs

Incrementing keys come from the database. A non-incrementing key is generated by the model's native unique id API: `uniqueIds()` and `newUniqueId()`, as Laravel's `HasUuids` and `HasUlids` define them from 9.30. Without it, register a generator for the key, or the copy throws `MissingPrimaryKeyGeneratorException`:

- ===Trait

  ```php
  $document->deepReplicate('pages')
      ->generate('uuid', fn () => (string) Str::uuid())
      ->configure('pages', fn (RelationRule $rule) => $rule->generate('uuid', fn () => (string) Str::uuid()))
      ->replicate();
  ```

- ===Facade

  ```php
  DeepReplicate::for($document)
      ->copy('pages')
      ->generate('uuid', fn () => (string) Str::uuid())
      ->configure('pages', fn (RelationRule $rule) => $rule->generate('uuid', fn () => (string) Str::uuid()))
      ->replicate();
  ```

Other columns listed in `uniqueIds()` get new values too.

### Timestamps and soft deletes

Copies get new `created_at` and `updated_at` values, custom column names included. `preserveTimestamps()` keeps the source values on every copy and pivot row, and `RelationRule::preserveTimestamps(false)` opts one path out. A soft-deleted source is restored on its copy; `preserveSoftDelete()` keeps its `deleted_at`.

### Model defaults

A model using the trait may return fallback settings from `deepReplicationDefaults()`. They apply only to paths the caller selects, and they can never select a path or change a strategy.

```php
protected function deepReplicationDefaults(): array
{
    return [
        'with' => ['status' => 'draft'],
        'paths' => [
            'items' => ['exclude' => ['external_id']],
        ],
    ];
}
```

The keys are `exclude`, `with`, `generate`, `transform`, `without_events` and `preserve_timestamps`, at the root and under `paths`. Builder settings win: `with` and `generate` merge per attribute, and the other keys are replaced when the builder sets them.
